# M1.60 — Foundation Audit

## Scope

Static audit of the M1.59 source tree before the M1 freeze.

## Inventory

- TypeScript source files: 224
- Root public export targets: 11
- Duplicate root exports: none
- Local import graph cycle detection: no cycles discovered by the audit resolver.

## Findings

### A. Public API surface is too broad

`packages/atrocity/src/index.ts` currently re-exports infrastructure namespaces
such as connection, transport, crypto, noise, auth, and signal in addition to
the public client facade.

This contradicts the M1.41 decision that internal subsystem implementations
should not be required as public SDK contracts.

**Action before freeze:** make the root package entry point export the stable
public API only. Keep internal exports available through an explicitly
internal/development entry point if needed.

### B. Protocol event bus contains `any`

`protocol/events/protocol-event-bus.ts` currently stores listeners using
`Set<(...args: any[]) => any>`.

**Action before freeze:** replace this storage representation with an erased
internal listener type or a typed dispatch wrapper. Public event contracts
already have explicit payload types.

### C. Composition root still contains a transport placeholder boundary

`app/atrocity-composition.ts` relies on an injected `sendProtocolNode` callback
because M1.36 transport/protocol composition is not yet an exact production
adapter.

This is acceptable as an M1 composition seam, but it must not be mistaken for
live WhatsApp transport integration.

**Action:** document this as an explicit adapter boundary and keep the live
target implementation deferred to M2.

### D. Persistence security is not production complete

Credential/session persistence currently uses checksum-based corruption
detection but is not an authenticated encrypted-at-rest secret store.

**Status:** M1 blocker for a production security claim, but not a blocker for
the architectural M1 freeze. Track as a M3 hardening requirement unless exact
deployment requirements require it earlier.

### E. Target protocol semantics remain provisional

Message/presence/receipt node fields are normalization hints, not byte-level
WAProto compatibility claims.

**Status:** intentionally deferred to M2.

## Layering result

No dependency cycle was discovered by the static relative-import resolver.
No connection-layer imports of feature implementation internals were found.

## Freeze readiness

M1 architecture is suitable for freeze after:
1. narrowing the root public export surface;
2. removing `any` from the event bus implementation;
3. adding a machine-readable audit checklist;
4. explicitly labeling target-specific placeholders as M2 compatibility seams.

## Not yet production-compatible

M1 is **not** evidence of live WhatsApp interoperability. That begins in M2.
