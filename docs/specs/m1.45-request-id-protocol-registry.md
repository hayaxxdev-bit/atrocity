# M1.45 — Request IDs & Protocol Registry

## Request IDs

`RequestIdGenerator` creates unique protocol request ids with:
- configurable prefix
- monotonic process-local counter
- timestamp component
- random suffix

`IqService.get()` and `IqService.set()` generate an id when the caller does
not supply one.

## Protocol registry

`ProtocolRegistry` centralizes inbound node dispatch.

Routes can match:
- tag
- attributes
- priority

Multiple matching routes may run, in descending priority order.

## Lifecycle

A route returns an unregister function. Consumers must unregister feature
handlers when their feature lifecycle ends.

## Ownership

The registry does not own transport, reconnect, or IQ correlation. It only
dispatches already-decoded protocol nodes.
