# M1.28 — Atomic Double Ratchet Receive

## Reference

Signal Double Ratchet defines the receive path so skipped keys, DH-ratchet
transitions, and message-key derivation happen before message decryption.
A failed authentication must not result in a state that silently advances
the session as though the message was accepted.

Reference:
https://signal.org/docs/specifications/doubleratchet/

## Implementation

Atrocity now snapshots:
- root/rachet state
- send/receive counters
- local/remote ratchet keys
- receiving-chain state
- MKSKIPPED

`receiveAndDecrypt()` performs derivation and the decrypt callback inside an
atomic boundary. On failure it restores the complete snapshot. On success
the derived state remains committed.

## Important property

A malformed/tampered ciphertext does not consume:
- the skipped message key
- the current chain step
- the DH-ratchet transition
- the message counter

## Limitation

The current transaction boundary is in-memory. Persistent session storage
must use the same snapshot/commit principle once M1.30 persistence exists.
