# M1.23 — XEd25519 / XEdDSA Compatibility

## Reference

Signal's XEdDSA specification defines signatures using the same Curve25519
Montgomery private/public key format as X25519. A Montgomery public `u`
coordinate is converted into a twisted Edwards point with:
`y = (u - 1) / (u + 1)` and sign bit zero.

For a Montgomery private scalar `k`, `calculate_key_pair(k)` computes
`E = kB`, takes `A.y = E.y`, sets `A.s = 0`, and uses `a = k` or `-k mod q`
depending on the sign of `E`.

XEd25519 signing uses SHA-512, 64 random bytes, hash_1 domain separation,
and produces `R || s`. Verification uses the converted Montgomery public key
and the EdDSA verification equation.

Reference:
https://signal.org/docs/specifications/xeddsa/

## Atrocity

M1.23 adds an explicit `XEd25519Signer` boundary and the `@noble/curves`
backend.

The signer is deliberately independent from:
- Noise
- X3DH
- WhatsApp registration
- pre-key storage

## Security

The XEdDSA specification requires fresh 64-byte random input for each
signature and warns that XEdDSA is randomized.

Atrocity therefore does not replace the random input with deterministic
Ed25519 signing.

## Important review gate

The implementation must pass the official XEdDSA test vectors before being
used for production Signal registration. Live WhatsApp registration remains
disabled until those vectors and interoperability tests pass.
