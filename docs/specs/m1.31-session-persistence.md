# M1.31 — Signal Session Persistence

## Scope

M1.31 introduces a versioned session persistence boundary.

## Record

A persisted session includes:
- schema version
- session id
- timestamps
- associated data
- Double Ratchet state
- skipped message keys

## Integrity

Each binary record contains:
- magic
- schema version
- payload length
- SHA-256 checksum of the payload
- payload

The checksum detects accidental corruption. It is **not authentication** and
must not be considered a substitute for encryption or an authenticated storage
layer.

## Atomic save

FileSignalSessionStore writes to a temporary file and atomically renames it
to the target path. Temporary files use restrictive `0600` permissions.

## Security boundary

Secrets are never serialized as JSON or logged. The persistence record is a
binary representation of cryptographic state.

## Limitation

The file store is not encrypted at rest yet. Production deployment must use an
encrypted secret store or an authenticated/encrypted database before durable
credentials are enabled.
