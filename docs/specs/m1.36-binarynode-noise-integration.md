# M1.36 — BinaryNode ↔ Noise Transport Integration

## Architecture

M1.36 introduces `WhatsAppProtocolTransport`:

`ProtocolNode`
→ `WABinaryCodec`
→ `WhatsAppNoiseTransport`
→ raw `Transport`

Inbound:

`raw Transport`
→ `WhatsAppNoiseTransport`
→ `WABinaryCodec`
→ `ProtocolNode`

## State

`idle → connecting → open → noise-ready → encrypted`

Failure transitions to `failed`; connection close transitions to `closed`.

## Ownership

`WhatsAppProtocolTransport` owns:
- node serialization orchestration
- Noise-frame orchestration
- encrypted send/receive boundary
- node size limits

It does not own:
- WebSocket implementation
- Noise handshake
- credential state
- authentication
- WABinary token tables

## Handshake separation

While the transport is `open` but not `encrypted`, inbound bytes are intentionally
ignored by the node stream and remain owned by the handshake/authentication
layer.

This prevents handshake protobuf messages from accidentally entering the
normal BinaryNode stream.
