# M1.35 — WhatsApp Noise Frame & Transport Adapter

## Current reference

Current Baileys constructs its Noise handler using `NOISE_WA_HEADER` and routes
encrypted transport through the Noise wrapper's `encodeFrame()` and
`decodeFrame()` methods.

References:
- https://github.com/WhiskeySockets/Baileys/blob/master/src/Socket/socket.ts
- https://github.com/WhiskeySockets/Baileys/blob/master/src/NoiseHandler/NoiseHandler.ts

## Atrocity

M1.35 introduces a target-specific frame boundary:
- `WhatsAppNoiseFrameCodec`
- `WhatsAppNoiseTransport`

The frame codec validates:
- target header
- declared payload length
- frame size
- ciphertext size
- malformed/truncated input

`WhatsAppNoiseTransport` binds an installed Noise transport cipher to the
frame codec.

## Important limitation

The exact byte-level WhatsApp Noise frame semantics are still treated as a
target adapter and must be verified against current reference vectors/source.
This milestone does not claim that the internal length framing is identical
to every version of the production service.

The adapter is intentionally isolated so the framing can change without
changing the generic Noise cipher state.
