# M2.5 — Complete WhatsApp Noise Handshake Orchestration

## Scope

M2.5 combines the three target handshake stages into one explicit state
machine:

`created → client-hello-ready → server-hello-processed → client-finish-ready → transport-ready`

The orchestration owns sequencing only.

## Delegation

- ClientHello builder owns ClientHello structure.
- ServerHello processor owns target-specific processing order.
- ClientFinish builder owns ClientFinish structure.
- Noise/crypto dependencies own cryptographic operations.
- WAProto codec owns wire encoding.
- Transport owns sending/receiving.

## Transcript

`transcriptFromSnapshot()` exports the three wire messages that were emitted
by the orchestrator.

Exact cryptographic checkpoints are intentionally not fabricated.

## Reference

Current Baileys sends an encoded ClientHello, decodes/processes ServerHello,
builds/encrypts ClientPayload into ClientFinish, sends the encoded
ClientFinish, then finalizes Noise initialization.
