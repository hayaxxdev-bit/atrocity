# M2.22 — Key-Bundle Repair Orchestrator

M2.22 composes digest observation, server pre-key reconciliation, pre-key
upload, optional signed-pre-key rotation, and final digest verification.

Flow:
`check → reconcile → repair → verify → repaired`

A healthy bundle is a no-op.

A repair is considered successful only when the final digest query returns
`match`.

Any upload/rotation/verification failure produces `failed`; the orchestrator
does not claim repaired.

Network and crypto operations remain owned by the existing specialized
components.
