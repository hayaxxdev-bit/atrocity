# M1.34 — WhatsApp Noise Finish Adapter

## Current reference

Current Baileys `socket.ts` processes the server handshake with:
`const keyEnc = noise.processHandshake(handshake, creds.noiseKey)`.

It then encrypts the selected `ClientPayload` using `noise.encrypt(...)`
and sends:

`clientFinish: { static: keyEnc, payload: payloadEnc }`

Finally it calls `noise.finishInit()`.

Reference:
https://github.com/WhiskeySockets/Baileys/blob/master/src/Socket/socket.ts

## Atrocity implementation

M1.34 adds the explicit `processServerHello()` dependency to
`WhatsAppAuthenticator`.

The adapter returns:
- `encryptedStatic`

The authenticator then:
1. validates the server hello;
2. invokes target-specific Noise processing;
3. builds login/registration ClientPayload;
4. encrypts payload with the same Noise state;
5. constructs `clientFinish.static` from the adapter result;
6. sends `clientFinish`;
7. calls `finishNoise()`;
8. persists state.

## Architectural rule

`WhatsAppAuthenticator` must not implement target-specific Noise math.

That belongs to the `processServerHello()` adapter so the generic Noise state
and the target protocol lifecycle remain independently testable.

## Limitation

M1.34 supplies the correct boundary but does not invent the concrete
WhatsApp server transcript implementation. Live interoperability still
requires a target-specific adapter backed by exact Noise/reference vectors.
