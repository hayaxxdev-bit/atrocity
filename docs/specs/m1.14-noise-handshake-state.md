# Atrocity M1.14 — Generic Noise HandshakeState

## Reference

Noise Protocol Framework revision 34, sections 5.3, 7.1, 7.3 and 9.

Reference: https://noiseprotocol.org/noise.pdf

## Implemented

- explicit initiator/responder pre-message patterns
- pre-message transcript hashing
- data-driven handshake message patterns
- `e` and `s` token processing
- `ee`, `es`, `se`, `ss` DH token processing
- `psk` token processing through `MixKeyAndHash`
- encrypted handshake static-key handling
- encrypted handshake payload handling
- concrete local/remote key validation
- full `NN` test handshake
- full `XX` test handshake
- transport `Split` transition

## Important correction

Pre-messages are public-key knowledge established before the handshake.
They are not opaque transcript labels. The implementation now hashes the
actual relevant public keys in initiator-then-responder order.

## Limitation

This is a generic Noise engine, not a WhatsApp implementation. Target
profiles must provide exact pattern, protocol name, prologue, key material,
framing, and application payload rules.

## Security note

Pattern construction validates core revision-34 constraints. Full expert
review and authoritative test-vector interoperability are still required
before declaring a production cryptographic profile complete.
