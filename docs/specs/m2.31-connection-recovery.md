# M2.31 — Connection Recovery State Machine

## Objective

Recover an authenticated protocol session after a transport or stream interruption without blindly rebuilding the entire client stack.

The recovery boundary owns lifecycle sequencing. It does not own transport I/O, authentication protocol details, stream framing, Signal state, or message encoding.

## States

```text
CONNECTED
   |
   v
DISCONNECTED
   |
   v
RECONNECTING
   |
   +---- failure ----> FAILED
   |
   v
RESYNCING
   |
   +---- failure ----> FAILED
   |
   v
CONNECTED
```

An explicitly invalid authenticated session inserts reauthentication:

```text
DISCONNECTED
   |
   v
RECONNECTING
   |
   v
REAUTHENTICATING
   |
   +---- failure ----> FAILED
   |
   v
RESYNCING
   |
   v
CONNECTED
```

## Responsibilities

### ConnectionRecoveryStateMachine

Owns valid state transitions and recovery snapshots.

### ConnectionRecoveryCoordinator

Sequences independent collaborators:

1. reconnect transport
2. reauthenticate only when the existing authenticated session is invalid
3. resynchronize protocol/session state
4. resume pending outbound messages
5. mark the lifecycle connected only after all recovery stages succeed

### Injected collaborators

- `reconnectTransport`
- `reauthenticate`
- `resync`
- `resumePendingMessages`

These functions are intentionally opaque to the recovery package.

## Invariants

- Recovery is single-flight.
- A failed recovery never reports `connected`.
- Reauthentication is not performed for ordinary transport/stream interruptions.
- Pending messages are resumed only after resynchronization succeeds.
- Recovery cannot silently transition around an invalid lifecycle state.
- Resetting from `failed` is explicit.

## Non-goals

M2.31 does not implement:

- socket backoff policy
- network dialing
- Noise handshake
- authentication payload construction
- Signal ratchet repair
- key-bundle repair
- stream feature negotiation
- message encoding

Those remain separate boundaries consumed by the coordinator.

## Relationship to M2.30

M2.30 proved message round-trip mechanics. M2.31 turns those mechanics into a recoverable connection lifecycle so the transport/session can be restored without discarding unrelated state.
