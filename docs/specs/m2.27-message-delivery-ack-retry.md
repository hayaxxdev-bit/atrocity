# M2.27 — Message Delivery / ACK / Retry State

M2.27 introduces a canonical message delivery state machine.

Happy path:
`created → encrypted → sent → server-acked → delivered → read`

Retry:
`sent → retry-required → encrypted`

Session repair:
`sent → session-repair-required → encrypted`

The tracker does not perform network work. `MessageDeliveryRuntime` maps
incoming target-specific receipt nodes to tracker events and optionally invokes
a retry executor.

This creates a single stateful surface for message delivery without coupling
Signal encryption to receipt semantics.
