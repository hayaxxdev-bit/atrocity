# M2.9 — Exact WABinary Compatibility

Current Baileys WABinary uses:
- control tags for list/dictionary/JID/binary/packed encodings;
- a single-byte token table;
- four double-byte dictionary pages;
- packed nibble/hex encodings;
- JID pair and device-JID encodings;
- nested node lists;
- binary length forms.

Reference:
https://github.com/WhiskeySockets/Baileys/blob/master/src/WABinary/constants.ts
https://github.com/WhiskeySockets/Baileys/blob/master/src/WABinary/encode.ts
https://github.com/WhiskeySockets/Baileys/blob/master/src/WABinary/decode.ts

Atrocity M2.9 closes the structural gaps in the prior WABinary profile:
- double-byte dictionary support;
- JID pair/device-JID support;
- representative nested/binary round-trips;
- profile-driven token mappings.

The complete current WhatsApp token tables are intentionally profile data rather
than hardcoded into codec control flow. A generated table can therefore be
updated independently when the reference vocabulary changes.

M2.9 establishes format compatibility mechanics. It does not claim that the
bundled representative token table is complete or that live WhatsApp
interoperability has been achieved.
