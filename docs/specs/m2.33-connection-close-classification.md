# M2.33 — Connection Close/Error Classification

## Objective

Normalize heterogeneous transport/protocol failures into explicit recovery actions before they enter the M2.31 lifecycle orchestration.

## Pipeline

```text
unknown error
      │
      ▼
CloseNormalizer
      │
      ▼
ConnectionCloseSignal
      │
      ▼
CloseClassifier
      │
      ▼
RecoveryAction
  ├── reconnect
  ├── reauthenticate
  ├── repair-session
  └── terminal
      │
      ▼
RecoveryRouter
      │
      ▼
M2.31 / repair / terminal boundary
```

## Classification

### Reconnect

Used for retryable transport/stream interruptions such as network loss, timeout, stream close, or server shutdown.

### Reauthenticate

Used when authentication/session credentials are no longer accepted and a fresh authentication lifecycle is required.

### Repair session

Used when the transport is usable but authenticated cryptographic/session state needs repair.

### Terminal

Used for non-retryable or protocol-invalid conditions.

## Invariants

- normalization converts unknown external error shapes into a stable internal signal
- classification is side-effect free
- router invokes exactly one action handler
- classifier never performs network I/O
- a protocol failure cannot silently become a reconnect
- the recovery state machine remains independent from error taxonomy

## Non-goals

M2.33 does not attempt to reproduce every upstream close code.

The mapping is an internal stable abstraction. Source adapters may translate their native close reason into this model without leaking dependency-specific enums into the core recovery package.
