# M2.18 — Server PreKey Reconciliation

M2.18 adds a decision layer between server key-bundle observations and the
local `PreKeyPool`.

Inputs:
- server pre-key count
- current server pre-key id (when known)
- current pre-key existence
- local available key count

Outputs:
- `no-action`
- `upload`

Reasons are explicit:
- server-count-zero
- server-count-below-threshold
- current-prekey-missing
- pool-at-target

`PreKeyReconciliationRunner` may generate and mark keys as pending upload, but
does not perform network I/O. Upload remains owned by the WhatsApp exchange
layer.

Reference:
https://github.com/WhiskeySockets/Baileys/blob/master/src/Socket/socket.ts
https://github.com/WhiskeySockets/Baileys/blob/master/src/Utils/signal.ts

Exact production threshold values remain configurable reference-version data.
