# M1.32 — Authentication & Session Store

## Scope

M1.32 introduces an aggregate persistence boundary for:
- authentication credentials
- Signal sessions

Credentials and sessions remain physically/logically separate records.

## Credential record

Credentials are encoded as a versioned binary record:
- magic
- schema version
- payload length
- checksum
- credential payload

The payload contains private credential material required by the local client.

## Aggregate store

`AtrocityStateStore` exposes:
- `loadCredentials`
- `saveCredentials`
- `loadSession`
- `saveSession`
- `deleteSession`
- `listSessions`
- `transaction`

Mutations are serialized through an in-process promise queue and persisted with
temp-file + atomic rename semantics.

## Security

Files are created with mode `0600`.
The checksum detects accidental corruption only. It is not authentication or
encryption.

Production deployments must add authenticated encryption at rest before
credential files are treated as secure storage.

## Deliberate non-goals

- database backend
- multi-process distributed locking
- encrypted secret store
- migration framework beyond the record version field
- direct WhatsApp registration
