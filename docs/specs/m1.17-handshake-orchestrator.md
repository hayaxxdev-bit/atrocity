# Atrocity M1.17 — Handshake Orchestrator

## Reference flow

Current Baileys socket code:
1. creates a fresh ephemeral Curve key pair;
2. creates the Noise wrapper;
3. creates/sends `HandshakeMessage.clientHello` containing the ephemeral public key;
4. decodes `serverHello`;
5. processes the Noise handshake;
6. builds a login or registration `ClientPayload`;
7. encrypts the payload through Noise;
8. sends `HandshakeMessage.clientFinish`;
9. finalizes the Noise connection and continues connection initialization.

Reference:
https://github.com/WhiskeySockets/Baileys/blob/master/src/Socket/socket.ts

## Atrocity design

`HandshakeOrchestrator` owns sequencing only. It does not own:
- WebSocket details
- Noise cryptography
- protobuf schema implementation
- registration/login payload generation
- persistence
- reconnect

Those are dependency-injected collaborators.

## State

`idle → transport-connected → client-hello-sent → server-hello-received
→ noise-processing → client-payload-encrypted → client-finish-sent
→ complete`

Any stage may transition to `failed`.

## Important limitation

M1.17 is a deterministic orchestration harness. It is not yet a live
WhatsApp login client. The exact Noise payload processing, authentication
credentials, registration/login node generation, and final post-handshake
initialization are still separate milestones.
