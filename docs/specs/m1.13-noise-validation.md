# Atrocity M1.13 — Noise Validation & Test Vectors

## Reference rules

Noise revision 34 specifies handshake-pattern validity constraints:
parties can only DH with keys they possess; each party sends `e` and `s`
at most once; each DH operation (`ee`, `es`, `se`, `ss`) occurs at most
once; and additional encryption/order constraints apply after static-key
DH operations.

Reference: https://noiseprotocol.org/noise.pdf

## Added

- structural pattern validation
- rejection of repeated DH operations
- rejection of repeated key transmission by one party
- test-vector schema
- development vector generator
- replay/contract tests

## Limitation

The development vector generator currently uses runtime-generated
X25519 keys and therefore is not a permanent byte-for-byte golden vector.
Production vectors must be committed as fixed fixtures generated from
authoritative Noise vectors (e.g. Cacophony/reference vectors) before
the engine is considered interoperably validated.
