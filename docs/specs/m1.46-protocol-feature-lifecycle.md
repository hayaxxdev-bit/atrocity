# M1.46 — Protocol Feature Lifecycle

## Scope

M1.46 introduces a feature lifecycle manager above the protocol registry and
IQ service.

Features declare:
- name
- version
- dependencies
- capabilities
- start()
- stop()

## Dependency ordering

Dependencies start before dependents.

Shutdown occurs in reverse order.

Example:

`iq → message → receipt`

starts:
`iq, message, receipt`

stops:
`receipt, message, iq`

## Failure handling

`startAll()` is transactional at the feature lifecycle level:
when a feature fails to start, already-started features are stopped in reverse
order.

## Registration

Registration returns a disposer. Active features cannot be silently
unregistered.

## Boundary

ProtocolFeatureManager does not own connection state or transport. It is
invoked by the connection lifecycle when the encrypted protocol stream is
ready.
