# M1.27 — Skipped Message Keys

## Reference

Double Ratchet revision 4 defines `MKSKIPPED` as a dictionary of skipped
message keys indexed by ratchet public key and message number. `MAX_SKIP`
limits the number of keys that may be skipped in a single chain to prevent a
malicious sender from causing excessive computation.

The receive algorithm:
1. tries `MKSKIPPED`;
2. performs a DH ratchet when a new remote ratchet key is seen;
3. stores skipped keys from the previous receiving chain using `PN`;
4. stores skipped keys up to the current message `N`;
5. advances once to derive the current message key.

Reference:
https://signal.org/docs/specifications/doubleratchet/

## Implemented

- `(DH public key, message number)` key indexing
- destructive consumption of skipped keys
- total and per-chain limits
- `MAX_SKIP` enforcement
- receive-path coordinator
- out-of-order key lookup
- skipped-key state boundary

## Security requirement

Ciphertext authentication failure must not permanently commit the state
mutations performed while deriving a message key. The production receive path
therefore needs transactional state/rollback around the full decrypt operation.

## Not yet implemented

- atomic session snapshots/rollback
- Signal message header encoding
- message AEAD construction
- persistent skipped-key storage
- header encryption
