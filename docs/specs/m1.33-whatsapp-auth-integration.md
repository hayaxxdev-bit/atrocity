# M1.33 — WhatsApp Authentication Integration

## Current reference flow

Current Baileys `socket.ts`:
- creates a fresh Curve/Noise ephemeral key for the connection
- constructs a Noise wrapper with the WhatsApp Noise header
- sends `HandshakeMessage.clientHello`
- waits for and decodes `serverHello`
- calls `processHandshake`
- chooses `generateRegistrationNode` or `generateLoginNode`
- protobuf-encodes the ClientPayload
- encrypts it through Noise
- sends `HandshakeMessage.clientFinish`
- finalizes the Noise session with `finishInit`

References:
https://github.com/WhiskeySockets/Baileys/blob/master/src/Socket/socket.ts
https://github.com/WhiskeySockets/Baileys/blob/master/src/Utils/validate-connection.ts

## Atrocity

M1.33 adds `WhatsAppAuthenticator` as a target-specific orchestration
boundary. Its dependencies provide:
- state loading
- Noise state
- handshake encode/decode
- raw transport
- login payload builder
- registration payload builder
- finalization
- persistence

## Security boundary

The orchestrator itself does not own private keys or manipulate the
credential store directly.

## Important limitation

This milestone is an orchestration harness. It is not a live WhatsApp login
implementation.

In particular, the current M1.33 `clientFinish.static` value is intentionally
not populated from a production `processHandshake()` return because that
target-specific coupling has not yet been implemented correctly.

A live-compatible implementation must complete the target-specific Noise
finish result and exact WAProto handshake payload semantics before deployment.
