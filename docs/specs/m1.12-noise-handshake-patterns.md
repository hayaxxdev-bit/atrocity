# Atrocity M1.12 — Noise Handshake Pattern Engine

## Reference

Noise revision 34 defines `HandshakeState` as a `SymmetricState` plus
local static/ephemeral and remote static/ephemeral keys, initiator role,
and a sequence of message patterns. Each message pattern contains tokens
from `e`, `s`, `ee`, `es`, `se`, `ss`; `psk` is specified separately.

Reference: https://noiseprotocol.org/noise_rev34.pdf

## Implementation

Atrocity now has:
- handshake pattern model
- token validation
- message sequencing
- local/remote ephemeral/static key storage
- token dispatch
- DH integration with SymmetricState
- encrypted payload handling
- explicit local/remote turn checks

## Limitation

This milestone is still not a production-complete Noise interpreter.
Pre-message key resolution, exact PSK semantics, fallback patterns,
all validity rules, and target-specific protocol profiles remain pending.

In particular, `preMessages` are not yet interpreted as key references;
the current harness only keeps deterministic transcript markers.

The engine must not be advertised as WhatsApp compatible until the exact
target pattern and all target-specific handshake parameters are verified.
