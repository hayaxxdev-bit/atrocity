# M2.8 — Post-Authentication Initialization

Current Baileys handles the `CB:success` path by updating server time,
checking/uploading pre-keys, sending active/passive initialization, validating
the key-bundle digest (with a fallback path), updating authenticated
credentials, and then publishing the open/connection state.

Reference:
https://github.com/WhiskeySockets/Baileys/blob/master/src/Socket/socket.ts

Atrocity models this as an explicit post-auth state machine.

The initializer owns sequencing only. Concrete pre-key upload, credential
persistence, presence IQ, and key-bundle digest are injected operations.

An `authenticated` result is emitted only after all required initialization
steps succeed.
