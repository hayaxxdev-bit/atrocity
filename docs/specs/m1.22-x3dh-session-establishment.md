# M1.22 — X3DH Session Establishment

## Verified Signal rules

X3DH uses X25519 (or X448) consistently for the DH identity, ephemeral,
signed-prekey, and one-time-prekey keys. It calculates:

`DH1 = DH(IK_A, SPK_B)`
`DH2 = DH(EK_A, IK_B)`
`DH3 = DH(EK_A, SPK_B)`
`DH4 = DH(EK_A, OPK_B)` when an OPK is present

and derives `SK` with the X3DH KDF. Associated data binds the two identity
public keys.

Reference:
https://signal.org/docs/specifications/x3dh/

## M1.22 design correction

Atrocity now separates:
- X25519 identity/DH key
- signing key used to authenticate the signed pre-key

The exact signing relationship is profile-dependent because standard X3DH
uses XEdDSA semantics over the curve-family identity key. Atrocity therefore
injects a `verifySignedPreKey()` callback rather than falsely treating a
raw Ed25519 public key as an X25519 DH identity.

## Implemented

- X3DH bundle validation
- signature-verification boundary
- DH1/DH2/DH3
- optional DH4
- X3DH KDF domain prefix
- associated-data binding
- responder derivation
- one-time-prekey consumption only after validation

## Not yet production-complete

- exact XEdDSA compatibility
- exact WhatsApp key encoding/identity semantics
- Double Ratchet
- Signal message serialization
- persistent session records
