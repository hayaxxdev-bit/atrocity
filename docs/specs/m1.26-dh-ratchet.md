# M1.26 — Double Ratchet DH Ratchet

## Reference

Current Signal Double Ratchet revision 4 describes these state variables:
`DHs`, `DHr`, `RK`, `CKs`, `CKr`, `Ns`, `Nr`, `PN`, and skipped-message key
storage. A new remote ratchet public key triggers a DH ratchet step before the
receiving chain advances.

A full DH ratchet step:
1. stores the previous sending-chain length in `PN`;
2. resets `Ns` and `Nr`;
3. performs DH with the current local ratchet key and new remote public key;
4. applies `KDF_RK` to obtain a new root key and receiving chain;
5. generates a new local ratchet key;
6. performs DH again;
7. applies `KDF_RK` again to obtain the new sending chain.

Reference:
https://signal.org/docs/specifications/doubleratchet/

## Implemented

- local/remote ratchet public keys
- `PN` tracking
- send/receive counters reset
- first root-KDF update for receiving chain
- new local ratchet key generation
- second root-KDF update for sending chain
- header projection `{ dh, pn, n }`

## Explicitly deferred

- skipped-message-key map
- `MAX_SKIP` enforcement
- message header serialization
- associated-data construction
- message encryption
- transactional rollback on failed receive
- header-encryption variant

The current class therefore implements the DH-ratchet state transition, not
the complete production decrypt path.
