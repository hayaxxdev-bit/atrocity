
# M2.6 — ClientPayload Foundation

Current Baileys builds a common ClientPayload base and then branches into
login and registration profiles. Login uses passive/pull semantics and
username/device; registration uses devicePairingData with passive/pull false.

Reference:
https://github.com/WhiskeySockets/Baileys/blob/master/src/Utils/validate-connection.ts

Atrocity M2.6 adds profile validation and a single adapter for building,
encoding, and round-tripping ClientPayload.

Exact byte-level compatibility remains dependent on captured/reference WAProto
vectors and current target metadata.
