# M2.34 — Recovery Composition Layer

## Objective

Compose the recovery boundaries introduced in M2.31–M2.33 without moving their responsibilities into a single manager.

## Composition

```text
ConnectionCloseSignal
        |
        v
CloseClassifier
        |
        v
ConnectionRecoveryComposer
   |         |          |          |
   v         v          v          v
reconnect  reauth    repair     terminal
   |         |          |
   v         v          v
caller     caller     caller
wires      wires      wires
M2.32      M2.31      repair
+M2.31     +auth      orchestrator
```

## Responsibilities

`ConnectionRecoveryComposer` owns only composition:

- classify the failure
- invoke exactly one action boundary
- prevent overlapping compositions
- return the selected action and recovery result

`RecoveryCompositionAdapterFactory` is intentionally semantic-free wiring. It does not decide whether an action should invoke M2.31, M2.32, or a repair orchestrator.

That ordering is owned by the caller because concrete production sequencing depends on the transport/session adapter.

## M2.31 / M2.32 / M2.33 ownership

- M2.31: lifecycle state machine and recovery sequencing
- M2.32: reconnect retry/backoff
- M2.33: failure normalization/classification
- M2.34: composition only

## Invariants

- one input failure is classified once per composition call
- exactly one action handler is executed
- composition has no timer/backoff behavior
- composition has no authentication/session semantics
- composition does not reinterpret action failures

## Non-goals

M2.34 does not add production socket integration or assume a specific sequencing between reconnect, authentication, and repair.
