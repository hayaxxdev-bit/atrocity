# Atrocity M1.15 — WhatsApp Noise Profile

## Verified current-reference facts

Current Baileys source defines:
- `NOISE_MODE = Noise_XX_25519_AESGCM_SHA256\0\0\0\0`
- `DICT_VERSION = 3`
- `NOISE_WA_HEADER = [87, 65, 6, DICT_VERSION]`
- WebSocket URL default: `wss://web.whatsapp.com/ws/chat`

Its current socket path creates a fresh Curve key pair per connection,
constructs a Noise handler with `NOISE_WA_HEADER`, sends
`HandshakeMessage.clientHello`, processes `serverHello`, encrypts the
protobuf `ClientPayload`, sends `clientFinish`, calls `noise.finishInit()`,
and only then starts keepalive.

Sources:
- https://github.com/WhiskeySockets/Baileys/blob/master/src/Defaults/index.ts
- https://github.com/WhiskeySockets/Baileys/blob/master/src/Socket/socket.ts

## Atrocity decision

Those target-specific constants are represented by `WhatsAppNoiseProfile`
and are not embedded in `NoiseEngine`.

## Not yet verified

- exact effective Noise prologue/transcript behavior
- exact routing-info effect on the Noise session
- complete handshake protobuf semantics
- exact client/server handshake frame sequencing
- complete post-handshake record framing

Therefore this milestone is a **target profile scaffold**, not a claim of
live WhatsApp compatibility.
