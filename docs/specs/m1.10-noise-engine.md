# Atrocity M1.10 — Noise Engine

## Scope

M1.10 introduces a generic Noise-oriented state boundary over the M1.9
cryptographic primitives.

## Components

- `NoiseProfile`: protocol parameters and prologue.
- `NoiseHandshake`: handshake lifecycle/state.
- `NoiseTransportCipher`: send/receive nonce state plus AEAD.
- `NoiseEngine`: orchestration.

## Important limitation

The included `TEST_NOISE_PROFILE` and handshake flow are a deterministic
development/interoperability harness, not a WhatsApp implementation.
They intentionally do not claim a specific production Noise pattern or
WhatsApp framing semantics.

## Invariants

- Noise does not depend on WABinary or WebSocket.
- Handshake state and transport cipher state are separate.
- Send/receive cipher keys are direction-specific.
- Nonce ownership belongs to the transport cipher state.
- Handshake failure is terminal for that Noise session.
- Application code cannot provide an arbitrary transport nonce.
- Raw key material is not exposed through lifecycle events.
- The exact target protocol profile must be supplied separately.
