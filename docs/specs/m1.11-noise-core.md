# Atrocity M1.11 — Noise Core

M1.11 promotes the previous Noise skeleton into a closer implementation
of the Noise Framework's symmetric/cipher state mechanics.

## Implemented concepts

- `CipherState`
- `SymmetricState`
- protocol-name initialization/padding
- `MixHash`
- `MixKey`
- `MixKeyAndHash`
- `EncryptAndHash`
- `DecryptAndHash`
- `Split`
- directional transport cipher states
- 64-bit nonce lifecycle
- AES-GCM Noise nonce encoding
- authenticated-decryption nonce preservation on failure

The specification defines the AES-GCM nonce as 32 zero bits followed by
the big-endian 64-bit Noise nonce.

Reference: Noise Protocol Framework revision 34, sections 5.1–5.2 and
12.4: https://noiseprotocol.org/noise.pdf

## Deliberate limitation

The public `NoiseEngine` still uses a small development handshake harness.
It is not yet a generic pattern interpreter and is not a WhatsApp profile.

The next milestone should implement handshake patterns and token
processing (`e`, `s`, `ee`, `es`, `se`, `ss`, `psk`, etc.) instead of
adding target-specific logic directly to the engine.
